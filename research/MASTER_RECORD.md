**Source:** `LOCAL_AI_PROJECT_MASTER.md` and the accompanying compiled project research record supplied in this project.

**Status:** Source-derived consolidated record.

## Purpose

This file is the bridge between the compiled research record and the structured Second Mind. It records the major requirement areas already established so later research can extend rather than repeatedly re-ask them.

## Established Direction

- Local-first personal AI.
- Initial AI inference is local-only.
- Existing PC is the initial platform.
- Build incrementally.
- Keep data portable and recoverable without the AI.
- Security is a core subsystem.
- Capability does not equal permission.
- The AI cannot grant itself authority.
- The user remains the final authority for persistent memory and consequential actions.
- Research before locking the software/model stack.

## Behaviour

The AI should challenge poor ideas, explain trade-offs, research changing information, distinguish facts/assumptions/recommendations, and avoid invention.

Apprentice rule: if it does not know, research; if research cannot resolve it, ask or say it does not know. Never knowingly guess.

## Memory / Second Mind

The source establishes a layered system consisting of raw archive, active knowledge, entities/concepts, relationships and selective retrieval. Personal memory and general knowledge are distinct but connected. Provenance, confidence, importance, freshness and history matter. Low-risk organisation may be autonomous; semantic meaning is protected.

The source explicitly establishes persistent decision history, authorised-source learning, contextual retrieval, deduplication with provenance, automatic consolidation, an Inbox/review path, correction learning and evolving research conclusions.

## Research

Research records should preserve sources, dates, verification/freshness, confidence, importance and reverification policy. Evidence should be evaluated on its actual quality. Conflicting credible sources should be investigated and preserved when unresolved. Historical conclusions should remain available when new evidence changes the current conclusion.

## PC Management

The eventual system should inspect hardware/software, diagnose performance, monitor resources and temperatures, organise files, find duplicates, identify unnecessary applications/services, recommend optimisation, install/update software when approved, troubleshoot interactively and eventually perform proactive maintenance.

Nothing changes on the PC without explicit approval. Protected/dangerous areas should not be casually modified or proposed for destructive operations.

## Security / Permissions

Permissions are risk-based and scoped. Permission levels include no external action, read-only, non-critical modification and consequential/external actions requiring approval; high-risk administration is avoided by default.

Project-folder authority inherits through files/subfolders unless explicitly protected. Secrets remain separately controlled. Network access is a separate permission boundary.

Explicit permissions are task-scoped and automatically expire when the authorised task finishes. The AI/security agent cannot self-grant permissions.

The AI cannot autonomously upload files or user data initially. Downloads require user permission. Download approval does not imply execution approval. Executables/scripts/installers require a separate explicit user command to run.

## External / Cloud Boundary

Initial AI inference is local-only. External web access is a separate future capability and must be controlled by the security/tool layer. External actions, uploads, logins, communications and transactions are not part of the initial unrestricted operating model.

## Architecture

The conceptual architecture is User → Interface → Boss/Personal AI → Model Router → Specialist Workers → Tools/MCP/Skills → Memory/Knowledge → Local Infrastructure. This remains a design hypothesis, not a locked implementation.

## Implementation Status

Phase 0 remains active. No production stack, model runtime, orchestration framework, database/vector store or agent implementation has been finally selected.
